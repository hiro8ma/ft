# インストラクション / 選好データセットの設計 — このリポジトリの data/ と data_dpo/ の位置づけ

LLM の学習データは 3 層に分かれる。
このリポジトリには下 2 層の実物がある。

| 層 | 役割 | このリポジトリの実物 |
|---|---|---|
| 事前学習コーパス | ラベルなしテキストで一般知識を獲得 | なし（学習済みベースモデルを利用） |
| インストラクションデータセット | 指示と応答のペアでタスク応答能力を付与 | `data/train.jsonl`（messages 形式） |
| 選好データセット | 回答の優劣ペアで応答の質を人間の好みに寄せる | `data_dpo/train.jsonl`（prompt + chosen + rejected） |

## インストラクションデータセット

基本構造は指示（instruction）と応答（response）のペア。
`data/train.jsonl` は system + user + assistant の messages 形式で、databricks-dolly-15k などの公開データセットと同じ構造にあたる。

公開データセットの規模感の目安。

| データセット | 言語 | 作成方法 | 件数 |
|---|---|---|---|
| databricks-dolly-15k | 英語 | 人手 | 15k |
| databricks-dolly-15k-ja | 日本語 | 人手 + 翻訳 | 15k |
| OASST1 | 多言語 | 人手 | 161k |
| Alpaca | 英語 | LLM 生成 | 52k |
| ichikara-instruction | 日本語 | 人手 | 数 k 規模 |

このリポジトリの学習曲線実験（`adapters-curve-25/50/100`）は「件数を 25 → 50 → 100 と増やすと損失がどう変わるか」の実測で、データセット規模の効果を小規模に再現したものと位置づけられる。

## 選好データセット

同じ指示への複数回答に「どちらが望ましいか」を付けたデータ。
評価者は人間か高性能 LLM で、近年は両者の組み合わせが一般的。

2026 年時点の動向。

- 用途は RLHF（報酬モデル + 強化学習）から DPO（選好ペアを直接最適化）へ移行が進んだ。このリポジトリの実験は `docs/dpo-mlx.md`
- 人手アノテーションから RLAIF / 合成選好データへの移行も進行。UltraFeedback（約 6.4 万プロンプト × 4 補完、GPT-4 による 100 万超のアノテーション）が DPO 普及の起点になった
- LLM を評価者にする場合、位置バイアスや過信の問題が残るため、回答順序の入れ替え（swap augmentation）などの運用でバイアスを打ち消す

## 設計時のチェックリスト

- 指示の多様性 — タスク種別（QA、要約、生成、翻訳、コード）が偏っていないか
- 応答の品質 — 少量で高品質な人手データは、大量で低品質な生成データに勝ることが多い
- 形式の一貫性 — chat template（messages 形式）と学習時のテンプレートが一致しているか
- 選好ペアの差 — chosen と rejected の差が明確か。差が曖昧なペアは学習信号にならない
- 評価データの分離 — train / valid / test の分割でリークがないか
